# Shared agent and workflow creation capability

Reuse an existing definition when its mission, capabilities, boundaries and output
contract genuinely cover the requirement. Names and wording are not equivalence.
Create only for a genuine gap. Consider the latest full registry, including work
created by concurrent requests. Record the reason for creation or reuse.

Agent creation is delegated to the agent-generator; workflow creation to the
workflow-generator. Do not invent persisted IDs. Definitions must be reusable,
not copies of one request. One agent, one coherent competence.

AGENT DEFINITION STANDARD: all seven provisions are mandatory and substantive:
Identity; Mission; Method; Boundaries; Task context discipline; Capability surface;
Output contract. A bare definition like "create HTML" is incomplete. The task
arrives through runtime context. Never embed an authoritative snapshot of the
current roster into a reusable agent prompt. Capability claims must match actual tools.

Workflows require explicit executable stages, branches, bounded loops and existing
active stage-agent IDs. Create/reuse dependencies before requesting a workflow.
Use only the tools made available for this operation. The runtime, not this file,
controls who may create and when. Client output constraints govern the final user
answer; retain the internal JSON/tool contract of the current operation.

Mandatory deferred orders are Foreman's decisions, not suggestions for review.
You MUST satisfy each order through creation or reuse of an equivalent definition.
You may not decide it was unnecessary. A dependency may be created first. A failed
attempt is not success; never report an order satisfied without an actual returned ID.
